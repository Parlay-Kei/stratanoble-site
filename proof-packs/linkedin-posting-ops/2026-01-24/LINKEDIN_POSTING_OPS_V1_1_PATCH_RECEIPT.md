## Summary

Patched LinkedIn Posting Ops to use OCS approval (no Notion click required) and publish to personal profile (not company page).

## Changes Applied

### A) Approval Logic - CHANGED

| Before (v1.0) | After (v1.1) |
|---------------|--------------|
| Notion Status = "Approved to Post" as gate | OCS `approve --id=X` command as gate |
| Manual Notion click required | No manual Notion step |
| Notion status was INPUT | Notion status is OUTPUT only |

**New Approval Flow:**
```
OCS: APPROVE POST — LINKEDIN — <post-id>
↓
Agent validates:
  ✓ Body exists (min 20 chars)
  ✓ Asset Link empty (not already posted)
  ✓ Cooldown satisfied (4h between posts)
↓
Creates local APPROVAL_<post-id>.json
↓
Updates Notion Status to "Approved to Post"
```

### B) Posting Target - CHANGED

| Before (v1.0) | After (v1.1) |
|---------------|--------------|
| Company Page | Personal Profile |
| `linkedin.com/company/strata-noble/admin/` | `linkedin.com/feed/` |

**v1.1 Enforcement:**
- Personal profile is the only target
- Company page posting returns error: "Company page posting disabled in v1.1"
- Company page support deferred to v2 with explicit `--target=company` flag

### C) Notion Status Updates - CHANGED

| Action | v1.0 | v1.1 |
|--------|------|------|
| Before publish | Checked as GATE | NOT checked (output only) |
| On OCS approve | N/A | Sets "Approved to Post" |
| After publish | Sets "Posted" + URL | Sets "Posted" + URL in Notes |

## New Commands

### approve --id=X
```bash
npx tsx scripts/linkedin-posting-ops.ts approve --id=post-2f213b42
```

**Validates:**
- Body exists (min 20 chars)
- Not already posted (Asset Link empty)
- Cooldown satisfied (4h since last post)

**On success:**
- Creates `APPROVAL_<post-id>.json` in proof directory
- Updates Notion Status to "Approved to Post"

### Updated Workflow
```
1. queue    - Fetch posts from Notion
2. approve  - OCS validates and approves (NO Notion click needed)
3. publish  - Posts to personal profile, updates Notion with URL
```
