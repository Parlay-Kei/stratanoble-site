# Strata Noble Consulting LLC
## IP Assignment & Licensing Outline

**Document Type:** Framework Outline (not legal advice)
**Version:** 1.0
**Date:** January 2026
**Purpose:** Define IP treatment when products spin out from the consulting entity

---

## 1. Overview

When a product spins out from Strata Noble Consulting LLC into a separate legal entity, intellectual property must be formally transferred. This outline describes the framework for IP assignment and any licensing arrangements between the parent consulting entity and the spinout.

**Important:** This is a planning framework. Actual IP assignments require attorney-drafted agreements specific to each spinout.

---

## 2. Pre-Spinout IP Ownership

**Default:** All IP developed within Strata Noble Consulting LLC is owned by the LLC.

This includes:
- Software code (source and compiled)
- Designs and UI/UX assets
- Documentation and processes
- Trademarks and brand elements
- Trade secrets and methodologies
- Customer lists (where applicable)

**Work Product from Client Engagements:**
- Client-specific deliverables: Owned by client per engagement contract
- Generic tools/methods developed during engagement: Owned by Strata Noble (unless otherwise specified)
- Improvements to existing Strata Noble tools: Owned by Strata Noble

---

## 3. IP Assignment at Spinout

### What Gets Assigned

When a product spins out, the following IP transfers to the new entity:

| IP Type | Assignment Approach |
|---------|---------------------|
| **Product Source Code** | Full assignment to spinout |
| **Product Brand/Trademark** | Assignment OR license (case-by-case) |
| **Product Documentation** | Full assignment to spinout |
| **Product-Specific Customer Data** | Transfer per data agreements |
| **Product-Specific Contracts** | Assignment or novation |

### What Stays with Consulting Entity

| IP Type | Retention Rationale |
|---------|---------------------|
| **Core Methodologies** | May be used in future consulting or products |
| **Generic Tools/Libraries** | Shared infrastructure |
| **Strata Noble Brand** | Parent brand protection |
| **Client Relationships** | Consulting relationship continuity |

## 4. Assignment Agreement Components

A formal IP Assignment Agreement should include:

### 4.1 Identification of IP
- Specific list of code repositories
- Trademark registrations (if any)
- Domain names
- Design files and assets
- Documentation

### 4.2 Assignment Language
Clear, unambiguous transfer of ownership:
> "Assignor hereby assigns, transfers, and conveys to Assignee all right, title, and interest in and to the Assigned IP..."

### 4.3 Representations & Warranties
- Assignor owns the IP
- IP is free of liens/encumbrances
- No third-party claims known
- No infringement issues known

### 4.4 Consideration
What the spinout provides in exchange:
- Cash payment
- Equity stake in spinout
- Revenue share arrangement
- Combination of above

### 4.5 Further Assurances
Commitment to execute additional documents as needed (e.g., trademark assignments, copyright registrations).

## 5. Licensing Back to Consulting Entity

In some cases, Strata Noble Consulting may want to continue using product IP for consulting purposes.

### 5.1 License Types

| License Type | Use Case | Terms |
|--------------|----------|-------|
| **Perpetual, Non-Exclusive** | Consulting uses product in client work | No fees; non-sublicensable |
| **Limited Internal Use** | Consulting uses product for internal ops | No fees; limited scope |
| **Revenue Share** | Consulting resells product to clients | % of revenue to spinout |

### 5.2 Standard License Terms

For internal/consulting use:
- **Scope:** Internal operations and client delivery only
- **Duration:** Perpetual
- **Exclusivity:** Non-exclusive
- **Fees:** None (consideration is part of spinout deal)
- **Sublicensing:** Not permitted without written consent

## 6. Founder Equity Treatment

When the Founder owns 100% of both entities:

| Scenario | Treatment |
|----------|-----------|
| **Self-Funded Spinout** | Founder owns 100% of both; IP assignment is internal transfer |
| **Investor-Backed Spinout** | IP assignment consideration may include equity in spinout for consulting entity |
| **Partial Sale** | IP valuation determines sale price; consulting entity may retain license |

**Key Principle:** Even when the same person owns both entities, formal IP assignment protects against future disputes (e.g., if investors come in later, or if entities are sold separately).

## 7. Spinout Checklist

When executing a spinout, complete these IP-related items:

### Pre-Formation
- [ ] Identify all IP to be transferred
- [ ] Document IP ownership chain
- [ ] Identify any third-party components (open source, licensed code)
- [ ] Determine licensing-back requirements

### At Formation
- [ ] Form new entity
- [ ] Draft IP Assignment Agreement
- [ ] Draft License Agreement (if applicable)
- [ ] Execute agreements

### Post-Formation
- [ ] Transfer domain names
- [ ] Update trademark registrations (if any)
- [ ] Update copyright notices in code
- [ ] Notify relevant third parties
- [ ] Update internal records

## 8. Special Considerations

### 8.1 Open Source Components
If the product includes open-source code:
- Document all open-source licenses
- Ensure compliance with license terms post-spinout
- Some licenses (GPL) have copyleft requirements

### 8.2 Third-Party APIs/Services
- Transfer or re-establish API keys
- Update billing for third-party services
- Notify vendors of entity change if required

### 8.3 Customer Data
- Review data processing agreements
- Ensure GDPR/CCPA compliance for data transfer
- Notify customers if required by agreements

### 8.4 Employee/Contractor IP
- Confirm IP assignment clauses in contractor agreements
- Ensure work-for-hire documentation is complete
- No loose ends on contributor IP

---

## 9. Valuation Considerations

When IP assignment involves consideration (cash, equity, revenue share):

| Method | Use Case |
|--------|----------|
| **Cost Approach** | Value = development costs invested |
| **Market Approach** | Value = comparable transactions |
| **Income Approach** | Value = projected revenue stream NPV |

For early-stage products, cost approach is often most practical.
