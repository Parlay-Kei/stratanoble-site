Global Bootstrap Contract

Governance Invariant

Core Invariant

ANX_ROOT Resolution is DETERMINISTIC and PROJECT-INDEPENDENT

Given any two projects A and B running the same mission:

  • resolve(ANX_ROOT, A) == resolve(ANX_ROOT, B)
  • load(AGENT_ROSTER, A) == load(AGENT_ROSTER, B)
  • gates(A) == gates(B)

Resolution Order (Strict)

Priority 1: $env:ANX_ROOT environment variable Priority 2: .anx-root pointer file in repo root Priority 3: Fallback default C:\Dev\.claude-anx

Protected Resources

Local repositories CANNOT override:

  • Agent roles or responsibilities (ROSTER.md)
  • Gate thresholds or approval requirements
  • Core routing rules (INTAKE.md)
  • Department prefixes

Policy Engine

Component #5 Governance

Purpose

Define what can run autonomously versus what needs approval, enforce caps, and trigger escalations.

Three Boundaries Strategy

Boundary 1: Autonomous Operations

These operations run without approval:

  • Intake and ticket creation
  • Routing and assignment
  • Drafting deliverables
  • Running validators
  • Writing receipts
  • Internal reporting
  • Requirements clarification (PM)

Boundary 2: Always Requires Approval

  • Client communication (beyond templates)
  • Publishing to production
  • Production deploys
  • Secrets and token access
  • Spend above caps
  • Resource deletion
  • Kill switch modifications

Boundary 3: Proof Before Ship

All delivery requires:

  • Proof pack validator PASS
  • QAG verdict PASS
  • Policy allows delivery action

Security Controls

Component #7 Protection

Purpose

Prevent accidental damage and data leakage through multiple layers of protection.

Control Layers

Path Allowlists

  • Restrict file system access to approved paths only
  • Prevent modification of system files
  • Enforce client namespace boundaries

Client Isolation

Each client has separate namespace:

clients/{client_id}/ ├── tickets/ (isolated per client) ├── proofs/ (isolated per client) └── artifacts/ (isolated per client)

Zero cross-client access - no client can read or write another client's data.

Daily Operating Loop

1. Intake Sweep

Convert every new request into tickets with receipts. Route requirements to PM.

2. Routing & Work Packets

OCS assigns owners (PM for requirements, ENGDEL for implementation), sets priorities.

3. Execute Safe Work First

Autonomous operations proceed immediately without approval.

QAG validates all work using PM's acceptance criteria, blocks delivery if not PASS.

5. Stage Delivery

Prepare delivery packets when policy allows.

6. Finance Capture

Record all runs and tool calls to state DB.
